Leva 01
Prompt Eng.
Comportamento · ↺ minuti
"Mostra il comportamento con esempi — non descriverlo con istruzioni."
Sotto-leve
A · Identità B · Obiettivo C · Ragionamento D · Formato E · Few-shot F · Casi limite G · Agentic
Principi
Identità prima: il ruolo guida tutto.
Esempi > istruzioni: un gold standard vale dieci regole.
Edge case espliciti: il modello non li inferisce da solo.
Passa oltre quando
Comportamento invariato dopo prompt ottimizzato + esempi, o prompt >5K token.
Leva 03
Tool Design
Capacità d'azione · ↺ ore
"Esponi intenzioni semantiche — non endpoint tecnici."
Sotto-leve
Nome (verbo_oggetto) Description Parametri Output contract Error contract Gerarchia Guardrail irrevers.
Principi
Description = cosa / quando / NON quando.
Ogni azione irreversibile richiede conferma.
Output pulito: niente ID tecnici o JSON verboso.
Passa oltre quando
Tool corretti ma risposte con info mancanti o obsolete → problema di conoscenza.
Leva 02
Scelta Modello
Qualità base · ↺ ore/giorni
"Non si sceglie il migliore — si sceglie il più adatto alle dimensioni critiche."
Sotto-leve
Dimensioni critiche Triangolo int./vel./costo Routing per task Golden dataset Benchmark vs. reale
Principi
Task-first: identifica le 2–3 dimensioni critiche prima di confrontare.
Routing: 70% small + 30% large → –80% costi.
Valuta sul tuo task, non sui benchmark pubblici.
Passa oltre quando
Il modello ha il profilo giusto e il problema persiste — non è lui il collo di bottiglia.
Leva 04
Knowledge / RAG
Conoscenza · ↺ giorni
"Il problema è quasi sempre nel chunking — non nel modello di retrieval."
Sotto-leve
Chunking Embedding model Vector store Retrieval ibrido Re-ranking Grounding Eval recall/faith.
Principi
Chunk autonomo: utile letto da solo, senza il documento.
Retrieval ibrido > semantico puro (BM25 + vettoriale).
Valuta recall e faithfulness separatamente per stadio.
Passa oltre quando
Conoscenza ok ma il task richiede coordinazione tra step multipli o agenti.
Leva M
Gestione Memoria
Continuità · ↺ giorni
"Memorizza decisioni — non dettagli. La memoria minima è la più robusta."
Sotto-leve (4 tipi)
In-context Episodica Semantica Procedurale Summarization progr. TTL e selezione
Principi
4 tipi diversi, 4 meccanismi diversi — non esiste "la memoria".
Input corrente ha sempre precedenza sul profilo memorizzato.
Privacy by design: TTL su tutto, no dati sensibili.
Passa oltre quando
Memoria ok ma comportamento sistematico impossibile da correggere col prompt.
Leva 05
Orchestrazione
Coordinazione · ↺ settimane
"Un agente singolo ben configurato batte quasi sempre un sistema multi-agente mal progettato."
Sotto-leve
Loop + terminazione Pattern composizione Topologie multi-ag. Schema di stato Partial failure HITL Tracing
Principi
Ogni loop ha un limite massimo di passi — senza eccezioni.
Singolo prima di multi-agente: esaurisci prima i limiti.
Lo stato è la mappa, non gli output dei passi precedenti.
Passa oltre quando
Workflow ok ma comportamento sistematico non correggibile — specializzazione profonda.
Leva 07
Fine-tuning
Specializzazione · ↺ mesi
"Insegna come rispondere — non cosa sa. Per conoscenza usa RAG."
Sotto-leve (3 tipi)
Tipo 1 · Stile/formato Tipo 2 · Ragionam. dominio Tipo 3 · Comportam./DPO Dataset quality Loss curve Test regressione
Principi
Test del prompt prima: 10 esempi gold che nessun prompt produce.
100 esempi eccellenti battono 1.000 mediocri.
Testa la regressione sui task non ottimizzati dopo ogni round.
Ultima leva
Solo dopo aver esaurito tutte le precedenti senza risultato sufficiente.
Leva 06 · Affidabilità
Testing & Valutazione
∞ Attivo in parallelo a tutte le leve · sempre · subito
"Non si migliora ciò che non si misura. La suite di test è più importante del prompt stesso."
30% casi limite nella suite — non solo casi tipici.
Dev set + held-out sempre separati. Gap >8pt = overfitting.
Soglie prima di misurare, non dopo aver visto i dati.
LLM-as-judge: valida su campione umano (corr. ≥ 0.85) prima di usarlo.
Diagnostica rapida — sintomo → leva

Fine-tuning · tipo 1 stile
Cinque principi trasversali
01
L'ordine è una gerarchia di costo. Esaurisci la leva meno costosa prima di passare alla successiva.
02
La qualità dei dati precede la qualità dell'algoritmo. Vale per RAG, fine-tuning e testing.
03
La semplicità è un valore. La complessità aggiuntiva deve comprare qualcosa di misurabile.
04
Valuta sul tuo task, non sui benchmark. 50 casi reali battono qualsiasi leaderboard pubblico.
05
I sistemi evolvono. Golden dataset e pipeline di eval sono ciò che li rende mantenibili nel tempo.
